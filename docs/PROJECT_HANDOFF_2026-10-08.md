## 1. 产品目标与当前定位

EvidenceGraph 目前优先作为**求职面试可演示的单篇论文产品**：用户上传文字可提取的
研究论文 PDF，后台解析原文并用本地模型生成一张有来源依据的概览图；点击节点或关系
查看原文证据卡片，选择卡片后带入类似 GPT 的对话框提问。图谱应帮助用户快速理解论文
做了什么，但不宣称完整抽取全文，也不把“引用的 block ID 存在”误称为“关系或回答
在语义上完全正确”。

跨论文联系、系统性质量评测、引用反向高亮及正式公网多用户部署仍未完成。
路线图中的阶段 0 已对三篇固定样本验收；阶段 1 已有可运行的作品集闭环，
但不能据此宣布整个阶段 1 或后续阶段验收完成。

## 3. 已实现并有记录的能力

1. **PDF 到可交互图谱**：25 MiB HTTP 上传上限；Docling 保存页码和稳定来源块；
   UI 显示上传、解析、证据、模型、验证和保存等里程碑进度及失败提示。
   Ontology v3.2 用跨学科核心类型表达论文概览，抽取按有界章节进行，
   每段最多一次有限修复，合并后仍校验结构、关系端点、当前 PDF 哈希和真实证据块。
   图谱最多 25 个节点/40 条关系；该上限和概览抽样会牺牲覆盖度。
2. **证据与对话**：节点/关系可拖动、点击，显示原文证据卡与 PDF 页链接；
   最多选择 12 个来源块带入提问。浏览器只发送 ID，服务端重查当前论文原文。
   没有手动选择时使用有界词汇/章节检索做单篇论文问答；回答消息和会话工作区可恢复。
   检索不是向量或图检索，可能漏掉改写、表格上下文或细节。
3. **Tutorial**：同页展示项目作者参与的 *Water Research* 论文的真实、已保存
   9 节点/12 关系图和三问三答；关系可打开来源卡。论文 DOI 为
   `10.1016/j.watres.2026.126464`。样例只读，不自动重新生成，也不切换访客的个人会话。
   历史验收发现一处回答有过宽的基线比较表述，不能把示例介绍成完全正确。
4. **会话与清理**：保留新建及历史对话；草稿、论文关联、证据选择和消息存储分别可恢复。
   历史条目有确认删除。独占论文删除切片会尝试停止相关本地任务并清除论文/图谱文件；
   共享或 Tutorial 引用的 PDF 不会被一个会话暗中物理删除。真实 Docling/Ollama
   运行中取消、跨存储原子性尚未端到端验收。
5. **本机身份边界**：游客持有服务端签发的 HttpOnly Cookie，上传后才获得该 PDF 的
   访问权；知道文档哈希不等于有权限。Mac 本地 `.env` 已启用
   `EVIDENCEGRAPH_REQUIRE_LOGIN_FOR_CHAT=true`：游客可上传、生成/浏览图谱和 Tutorial，
   提问、私人历史与会话操作需注册登录。登录使用 Argon2id 密码哈希和可撤销会话 Cookie；
   本浏览器游客论文授权可在登录时转移给账号。旧客户端 ID 会话未被自动认领或删除。

最新记录的本地验证（2026-10-07，**本次未重跑**）：Python 437 通过、4 个 Docker
测试按默认配置跳过；React 40 通过并成功构建；Ruff 和 Pyrefly 通过。账号正向流程
主要由临时数据库自动测试覆盖，用户之后报告本机测试正常；这不等于公网安全验收。
详细操作和备份位置见 `docs/DEMO_RUNBOOK.md`。

## 4. 尚未完成或尚未验收

**公网开放前的阻断项**：Cookie 登录下的 CSRF 防护；按账号和 IP 的注册、上传、
解析/模型推理配额与限流；HTTPS、`Secure` Cookie、可信反向代理和真实客户端 IP 配置；
账号恢复/删除与数据保留政策；过期游客文件清理；备份**恢复**演练；运行中容器的
跨用户权限、删除和任务取消端到端验收。`AUTH_SECRET` 等旧全局门槛与游客公开端点
还需核查。完成前只应本地或受控演示，不开放公网自由上传。

**产品与质量**：不同学科固定样本的人审图谱评测；证据是否真的支持关系和回答的
语义评估；模型失败率、冷启动/并发、长 PDF 与扫描件等边界测量；图谱或回答引用的
更精确 PDF 坐标高亮。阶段 2 的跨论文联系、阶段 3 的自动引用反向高亮仍未完成。
当前单篇问答是有界词汇检索或用户手动选证据，不应宣传成完整 RAG/图检索。

**版本与部署**：大量 Mac 改动仍未提交/推送；Windows 克隆未自动同步。
Windows 部署、域名购买、公开发布均没有因本交接文档获得授权。

## 5. 建议的下一步顺序（一次只做一个可测试切片）

1. **新会话先重建事实基线**：读 `AGENTS.md`、本文件、路线图最新章节和演示手册；
   检查 Mac `git status`/差异，不覆盖未提交改动；确认 Docker、模型链路与测试是否仍可用，
   但启动/重建前先与用户确认目标与影响。
2. **优先做 CSRF 的最小闭环**：梳理 Cookie 认证的状态变更接口，设计并测试浏览器
   合法请求、跨站请求拒绝及 Tutorial/上传例外。先说明会改哪些文件、前后端怎样传令牌
   或校验来源，再实施；不要只给登录页加一个视觉 token 就算完成。
3. **随后做可量化配额**：至少覆盖注册尝试、PDF 上传、Docling/模型任务与提问，
   按账号和 IP 设边界，并验证重复请求、并发、重启后的表现及 429 用户提示。
   具体额度应根据 Windows 模型和解析资源实测，再与用户确认。
4. **公开部署之前**：先整理/测试现有未提交改动并由用户确认是否提交/推送；
   核查 Windows 克隆和部署目标；完成 HTTPS/反向代理、Cookie、备份恢复及安全验收，
   再讨论域名和发布。不要为了上线而跳过阻断项。
5. **产品质量并行准备但不要冒充验收**：用工程、理科、社科、医科的固定论文
   建小型人工评测集，记录抽取覆盖、错误边、引用支持性、耗时与失败例；
   再决定是否调 ontology、分段、模型或检索，而不是仅凭一张好看的图做判断。
